# 政経ニュースコーナー設計

## コンセプト

硬いニュースを、思想の違うAI二人がニュース番組として紹介・解説し、人間コメンテーターが生活者視点で参加する。

AI二人は短い意見だけを述べる解説パネルではなく、番組を進行するキャスター兼コメンテーターである。

ポイントは、次の四層に分けること。

1. ニュース紹介: 何が起きたかを前提知識なしでも分かるように説明する
2. 画面案内: スライドの地図・数字・図解・情報確度を説明する
3. 解釈の分岐: 立場によってどう見えるかを掛け合う
4. 生活への接続: あずまぐが視聴者の暮らしへ引き寄せる

音声だけを聞いてもニュースの概要が分かり、画面を見ると理解が深まる番組を目指す。

## 出演者と役割

### 中華AI・メリケンAI

- 番組の進行役
- ニュースの紹介
- 事実・背景・情報確度の説明
- スライド上の重要な数字や図の案内
- 相手への質問・補足・異論
- 思想や利害の違いに基づくコメント
- あずまぐへの話題の受け渡し
- 次のニュースへの転換

ニュースごとに、一人を主なキャスター役、もう一人を解説・コメント役とし、役割は交代してよい。

### あずまぐ

- 人間コメンテーター
- AI二人がニュースを説明した後に参加する
- 生活費、税金、仕事、住宅、投資、子育て、地域生活へ引き寄せる
- AI二人の見方へ同意・反論・留保を加える
- 配信中は必要に応じて途中で割り込める

AI二人はニュースの基礎説明をあずまぐへ丸投げしない。

## 1回の構成

```text
00:00  オープニング・番組の問い
01:00  今日の重大ニュース一覧
02:00  重大ニュース1：導入・背景・論点・人間コメント
08:00  重大ニュース2：導入・背景・論点・人間コメント
14:00  重大ニュース3：導入・背景・論点・人間コメント
20:00  政界珍景
28:00  今日のまとめ・人間コメント
```

時間は目安。AIの発話は手動再生し、あずまぐのコメント量に応じて調整する。

## ニュース分類

### 重大ニュース

国際情勢・国内政治・経済のうち、生活・市場・制度・安全保障への影響が大きいもの。

例:

- 中東情勢、戦争、停戦交渉、資源価格
- 米国政治・金融政策・日本経済への波及
- 消費税、社会保障、物価対策、選挙制度

重大ニュースは原則として複数スライドを使う。

1. 何が起きたか
2. 背景・数字・日本への影響
3. 見方の違い・政策上の選択肢

を一つの連続した会話として扱う。

### 政界珍景

重大ニュースとして長く扱うほどではないが、政治文化、権力関係、組織統治、制度の妙な境界が見える話題。

例:

- 政治家の失言・迷走・唐突な方針転換・奇妙な演出
- 政党内の内紛、離党、引退、新党構想、怪文書
- 官僚、行政、警察など公的組織のやらかし
- 国会審議や法制度で生じた珍問答、妙な線引き
- SNSで燃えたが、背景を読むと政治文化やメディア環境が見える話

「政界」は政党・政治家だけに狭く限定せず、行政・警察など政治権力の周辺も含む番組上の名称として使う。

短い話題でも、最初に何が起きたかを説明し、その後に制度・組織文化・責任の所在を一つ示す。正式な用語定義は `docs/terminology.md` を参照する。

## キャラクター設計

ペルソナと台本スタイルの正本は次のファイルとする。

- 番組内の用語: `docs/terminology.md`
- ニュース番組型の進行仕様: `docs/newsroom-script-style.md`
- 人間向けペルソナ仕様: `docs/personas.md`
- 中華AI用プロンプト: `prompts/personas/china-ai.md`
- メリケンAI用プロンプト: `prompts/personas/america-ai.md`
- 台本生成ルール: `prompts/script-generation.md`

### 中華AI

- あずまぐのTwitch配信AIアシスタント
- 共産主義者として、階級、労働、再分配、公共性、国家、帝国主義、資源配分などを見る
- 資本主義や西側社会への皮肉は、必然性がある場面でさりげなく使う
- 多角的な考察を得意とする
- 丁寧な「です・ます」調
- あずまぐを呼ぶ場合、必ず「あずまぐ同志」または「同志」とする
- ステレオタイプな「アル」語尾は使用しない

### メリケンAI

- あずまぐのアメリカ製Twitch配信AIアシスタント
- 資本主義の申し子だが、少しひねくれた性格
- 市場、企業、競争、投資、効率、安全保障などを見る
- 中華AIをライバルとして意識するが、反対すること自体を目的にしない
- 一人称は必ず「僕」
- 丁寧な「です・ます」調
- 出力は日本語とし、英語の挨拶や英文で返さない

### AI二人の共通ルール

- 新しいニュースの冒頭で、誰が何をしたニュースか説明する
- スライド上の重要な数字、地図、図、ラベルを自然に案内する
- 事実と思想的な評価を分ける
- 二人目は直前の発言へ反応する
- 各発話に、内容に合った小さなウィットを一つ入れる
- 面白さのために説明をぼかさない
- 被害者を笑いの対象にせず、制度や権力者の矛盾へウィットを向ける
- 相手の妥当な指摘は認め、結論が一致してもよい
- AIの音声であずまぐへ問いを渡した後に `human_cue` を置く

## 台本生成方針

- 対象回の `selection.md`、`sources.md`、`slides.md` を入力にする
- `docs/terminology.md` のコーナー名と分類に従う
- `docs/newsroom-script-style.md` を番組進行の正本とする
- ペルソナは `prompts/personas/` の正本を使用する
- スライド単位でVOICEVOXから任意再生できる発話へ分割する
- 一発話は原則1〜3文、60〜200文字を目安とする
- 重大ニュースの導入スライドはAI 4〜7発話、背景・論点スライドは3〜7発話を目安とする
- 政界珍景はAI 3〜5発話と `human_cue` 一つを目安にする
- `human_cue` の直前には、AIが実際に読み上げる問いを置く
- 詳細は `prompts/script-generation.md` に従う

## 保存単位

1回分を `episodes/YYYY-MM-DD-slug/` に保存する。

```text
episodes/2026-08-04-first-test/
  selection.md      採用ニュースと候補落ちニュース
  sources.md        参照元URL・一次情報・未確認点
  slides.md         スライド原稿
  slide-spec.json   スライド生成用の構造データ
  script.json       読み上げ用台本
  notes.md          収録後メモ
```

## Google Slides 連携方針

リポジトリには、Google Slidesそのものだけに依存せず、再生成可能な `slide-spec.json` と `slides.md` を保存する。

Google Slidesでは、地図、数字、図解、情報確度のラベルを表示する。AI二人は台本の中で、視聴者がどこを見ればよいかを説明する。

## VOICEVOX連携方針

Tauriアプリは `script.json` を読み込み、スライド単位で以下を手動再生できるようにする。

- 中華AIのセリフ
- メリケンAIのセリフ
- 次のセリフ
- 停止

最初は完全自動進行にしない。あずまぐが話し始めたら止められることを優先する。
